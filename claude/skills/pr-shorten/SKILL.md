# PR 説明文の短縮

既存 PR の本文を、サブエージェントに書き直させて短縮し、検品して反映する。
本文構造の原則は `create-pr` スキルの「description 構造の原則（限定合理性の応用）」に従う（重複定義しない）。create-pr との方針差分は 1 点だけ: create-pr は新規起草なので件数・識別子などを省いてよいが、本スキルは既存本文の事実を**削除せず**、省略対象は折りたたみへ移す。また既存 PR の短縮では `## TL;DR` を新設しない（元にあれば先頭に保つ。無ければ常時表示の先頭 3〜5 行が結論・影響範囲・注意点になっていればよい）。本スキルは**既存 PR の本文を後から短縮する手順**に特化する。

## 用語

- **常時表示**: すべての `<details>…</details>` の外側にあるテキスト（最初の `<details>` より前、ではない。節ごとに折りたたみが複数あり得る）
- **計測コマンド**（起草サブエージェントへの指示と親の検品の両方で同じものを使う。`wc -m` は必ず `LC_ALL=C.UTF-8` 付き。`LC_ALL=C` だとバイト数になり日本語で約 3 倍になる）
  - 常時表示: `perl -0pe 's/<details\b[^>]*>.*?<\/details>//gsi' <file> | LC_ALL=C.UTF-8 wc -m`
  - 常時表示（動作確認を除く）: `perl -0pe 's/## 動作確認.*?(?=\n## |\z)//s' <file> | perl -0pe 's/<details\b[^>]*>.*?<\/details>//gsi' | LC_ALL=C.UTF-8 wc -m`
  - 常時表示の行数（空行を除く）: `perl -0pe 's/<details\b[^>]*>.*?<\/details>//gsi' <file> | grep -c '\S'`（空行込みは `| wc -l`）
  - 全体: `LC_ALL=C.UTF-8 wc -m <file>`
  - `## 動作確認` の該当項目（何を確認して結果がどうだったか）は常時表示に残すため、字数目標（600〜900 字）と手順 1 の「900 字以下なら短縮不要」の判断は**動作確認を除く常時表示**の値で行う。起草サブエージェントは動作確認を含む常時表示と除く常時表示、および常時表示の行数（空行を除く）を報告する
- **優先順位**: 事実の保持 > 常時表示の必須項目（テンプレート見出し・注意点・根拠 URL） > 字数目標

## 使用方法

```
/pr-shorten <PR番号 or URL> [--draft-only]
```

- `$ARGUMENTS` の最初の PR 番号 or URL を対象とする。引数が無ければ PR 番号を尋ねる
- `--draft-only` または「案だけ」と言われたときは、PR を更新せず案を提示して止まる
- それ以外は更新まで行う（このスキルの起動がその許可。ただし実行環境の権限設定が優先する）

## 前提

- `gh` で対象リポジトリにアクセスできること
- 対象ブランチのチェックアウトは不要（`gh` だけで完結する。pr-review-loop と違い worktree の照合はしない。cwd のファイルも見ない）
- サブエージェントの `model` は `subagent-model-policy` スキルに従って必ず明示する（必要なら Skill ツールで読む）。本文の書き直しは文章作成ゆえ `model: "sonnet"`
- 親セッションは起草をサブエージェントに委譲し、自分は検品と反映を担う
- PR が見つからない、`gh pr edit` が失敗したときは、エラー内容と（あれば）after ファイルのパスを報告して止める。最終行に `⛔ pr-shorten 失敗 (PR #<N>)` を出す（PR 番号が取れていなければ `(PR 不明)`）

## 手順

### 1. 現状取得・退避・事前確認

- `gh pr view <PR番号 or URL> --json number,title,body,url,baseRefName` で取得する。以降の `<N>` はこの number、`<URL>` はこの url を指す
- 以降の `gh pr view` / `gh pr edit` には `<URL>` を渡す（cwd と別リポジトリの PR でも正しい PR に効く。`gh pr edit <N>` は cwd のリポジトリを対象にするため）。`<N>` はファイル名・完了マーカー用
- 退避: `f=<scratchpad>/pr-shorten-<N>-before-$(date +%Y%m%d-%H%M%S).md; gh pr view <URL> --json body -q .body > "$f" && [ -s "$f" ] && echo "$f" || { rm -f "$f"; false; }`。表示されたパスを以降の before として使う（シェル変数は Bash 呼び出しをまたいで残らないため、`$(date …)` を再展開したり文字のままサブエージェントに渡したりしない）。何も表示されなければ gh が失敗したか本文が空（空ファイルは同じコマンド内で削除済み）。失敗扱いとして前提の失敗時手順へ。毎回、実行時点の本文をタイムスタンプ付きで保存する（再実行しても最初の原本が残る。以降「before」は今回保存したこのファイルを指す。after は `pr-shorten-<N>-after.md` のまま上書き可。scratchpad はセッション固有の一時ディレクトリ。Claude Code では環境情報に示される Scratchpad directory を使う）。計測コマンドで before の常時表示（動作確認を含む／除く）・全体の字数を記録する
- **短縮不要の判断**: before の常時表示（動作確認を除く）が 900 字以下、かつ常時表示が 50 行以内（空行を除く）なら短縮不要と判断し（`--draft-only` と同時に当てはまる場合も短縮不要が優先）、その旨と字数を報告して終える（完了マーカーは `✅ pr-shorten 完了 (PR #<N>) 短縮不要`）
- テンプレート確認: `gh api repos/<owner>/<repo>/contents/.github/pull_request_template.md -H 'Accept: application/vnd.github.raw'` と `.github/PULL_REQUEST_TEMPLATE.md`（owner/repo は `<URL>` から取る）。あれば見出し一覧（`grep '^#'`）を起草プロンプトに渡す。無ければ「テンプレート無し」として進める

### 2. 起草をサブエージェントに委譲（`model: "sonnet"`）

プロンプトに必ず含めること:

- 元本文（before ファイル）の絶対パスと、PR のタイトル・URL・base。元本文はファイルを実際に読むこと
- `cat ~/.claude/skills/create-pr/SKILL.md` を Bash で実行し、「description 構造の原則（限定合理性の応用）」節を実際に読むこと（サブエージェントには親の文脈が渡らず、Read は絶対パス必須のため `~` が失敗し得る）
- 出力先ファイル（`<scratchpad>/pr-shorten-<N>-after.md`）。**PR 自体は更新しない**（`gh pr edit` を実行しない）
- 常時表示の字数・行数の目標は create-pr の「description 構造の原則」と同じ（`## 動作確認` を除いて数える）。優先順位は上記「用語」のとおり。「30 秒で『なぜ・何を・何に気をつけるか』を掴める」こと
- 常時表示に残すもの: 背景（根拠 URL は残す）、変更内容の要点、レビュアー・利用者が踏みそうな注意点（破壊的変更、移行手順、環境依存の落とし穴）、動作確認の該当項目（コマンド／観点ごとに 1 行の結果。未実施・未確認の印も含む。詳細は節内で折りたたむ）、未確認・スコープ外の 1 行要約
- 折りたたみに入れるもの: 動作確認の詳細（環境の補足、エラーの内訳、原因分析、代替手順など。節内の `<details>`）、実機確認で裏付けた事項、未確認事項の詳細、レビューで本 PR 外とした指摘の詳細、変更内容・注意点の補足
- `## 動作確認` の扱い・動作確認の具体形・可視部分の行数目安・diff 由来情報の扱い・重複排除・見出しの考え方は create-pr に従う。事実・数値・未確認の印は落とさない。元本文の動作確認が表なら、表の行は 1 行ずつ短くして残してよい。「対象外とした観点」は元本文に当たる記述があるときだけ 1 行にまとめる（元に無い対象外の判断は足さない）
- 件数・実装識別子・多数のファイルパスなど create-pr が省略対象とするものは、削除せず折りたたみへ移す（上記の方針差分）
- 折りたたみ内も冗長表現は削るが、**事実・数値・判断理由は落とさない**
- 「レビューでの追加変更」のような経緯ベースの節は独立させず、変更内容・注意点に吸収する（レビュアーには経緯より現状が要る）
- 元に無い事実を足さない。曖昧化もしない（例: 「ポートを変更」ではなく「ホスト 4566 → コンテナ 8333」）
- 元本文で「未確認」「推測」とされている項目は、確認済みに格上げしない。推測と確認済み事実の区別を元のまま保つ
- PR テンプレートの見出し一覧（親が渡す。無ければ「テンプレート無し」）。テンプレートがあれば土台にし、見出し・順序・構造を変えない（リネーム・並べ替え・削除をしない）。見出しは常時表示に残して中身の詳細だけ畳む（節ごと畳まない）。元本文に `## TL;DR` があれば先頭に保つ。無い場合も新設はしない。先頭 3〜5 行が結論・影響範囲・注意点になるよう常時表示の順序を整える
- `<details><summary>…</summary>` の後に空行を入れる（中の Markdown を効かせるため）。`<details>` は入れ子にしない
- 末尾の `🤖 Generated with [Claude Code](https://claude.com/claude-code)` 行があれば残す
- 文体は元に合わせる（体言止め・箇条書き）
- 完了報告前に、上記の計測コマンドを実際に実行して実測値（常時表示（動作確認を含む／除く）・常時表示の行数（空行を除く）・全体）を報告する（見積もりで書かない）。元本文の URL・数値を `grep` で実際に突き合わせ、欠落が無いことを確認してから報告する。完了報告には全文も含める

サブエージェントが走っている間、自分で同じ本文を書き直して重複作業しない。待つ。

### 3. 検品（親が行う）

起草物（after ファイル）を `Read` で読み、同じ計測コマンドで実測する。優先順位は「事実の保持 > 常時表示の必須項目 > 字数目標」。チェックリスト:

- 常時表示（動作確認を除く）が目標字数内か
- `## 動作確認` の該当項目（何を確認して結果がどうだったか。未実施・未確認の印を含む）が常時表示で見えていること、詳細が節内の `<details>` に折りたたまれていること（節ごと畳まれていない）、事実・数値が元本文から欠けていないこと
- 常時表示が空行を除いて 50 行以内か（目標値。超過なら動作確認以外の節の詳細を畳み直す）
- テンプレートがある場合、見出しの順序・文言が元のテンプレートのまま保たれていること（リネーム・並べ替え・削除が無い）
- 元本文の固有名詞・数値・URL が、折りたたみ含めてどこかに残っているか。`grep` で突き合わせる（出力が空なら合格）
  - URL: `comm -23 <(grep -oE 'https?://[^ )>]+' before | sort -u) <(grep -oE 'https?://[^ )>]+' after | sort -u)`
  - 数値: 同じ形で `grep -oE '[0-9][0-9.,]*'`（番号付きリストの `1.` 等で雑音が出るため、出力は目で判断する。箇条書き化による差は欠落ではない）
  - バッククォート識別子: 同じ形で `` grep -oE '`[^`]+`' ``
  - 「未確認」「推測」の語が before にあれば after にも残っているか
- 事実の追加・曖昧化が無いか。「未確認」「推測」が確認済みに書き換わっていないか
- テンプレート見出しが常時表示に残っているか。`## TL;DR` が元にあれば保たれているか、無ければ先頭 3〜5 行が結論・影響範囲・注意点になっているか
- 件数・実装識別子が常時表示に残っていないか（折りたたみ側にあるか）
- `<summary>` 後の空行、末尾の Generated 行、ファイル末尾の改行
- 不足があれば `SendMessage` で同じサブエージェントに差し戻す（新規起動より文脈が残る）。差し戻しは最大 2 回。それでも 900 字を超えるなら、超過の理由を添えて報告し先へ進む

### 4. 反映

- `--draft-only` の場合は反映せず、手順 5 へ進む（反映後の確認は省略）
- それ以外は `gh pr edit <URL> --body-file <scratchpad>/pr-shorten-<N>-after.md` で反映する（完成した全文のファイルを渡す）
- 反映後に `diff <(gh pr view <URL> --json body -q .body) <scratchpad>/pr-shorten-<N>-after.md` で一致を確認する（空行だけの差は許容。jq 出力の末尾改行で 1 字ずれ得るため `wc -m` 比較はしない）

### 5. 報告

`--draft-only` でも次の定型で報告する（その場合は案の全文を添える）:

```
📊 PR 本文短縮レポート
PR番号 / URL

| 区分 | 文字数 |
|---|---|
| 旧本文（全体） | |
| 旧本文（常時表示） | |
| 新・常時表示 | |
| 新・常時表示（動作確認除く） | |
| 新・常時表示（行数、空行除く） | |
| 新・全体 | |

### 常時表示に残したもの
- 

### 折りたたみに移したもの
- 

### 落としたもの
- 無し（あれば列挙）

### 退避先
- <scratchpad>/pr-shorten-<N>-before-<YYYYMMDD-HHMMSS>.md（今回保存したもの）
```

- 全体字数があまり減らない場合は「折りたたみ内の事実を落とさぬ方針ゆえ」と添え、追加で削る場合は間引く節を指定してもらう旨を一言添える（質問にはしない。回答待ちなのに完了マーカーが出ると、起動側が完了と誤検知するため）
- 完了マーカー: 最終メッセージの**最後の行**に `✅ pr-shorten 完了 (PR #<N>)` を出す（`--draft-only` で止めたときは `⏸ pr-shorten 案のみ (PR #<N>)`）。起動側はこの行で完了を検知する

## 注意

- 目的は全体の文字数削減ではなく、**常時表示の認知負荷の削減**。全体が数 % しか減らなくても、常時表示が 1/4 になれば成功（実績の 1 例: 元 3,350 字 → 常時表示 798 字 / 全体 3,164 字。全体は 186 / 3,350 ≒ 6% 減、常時表示は 798 / 3,350 ≒ 24% で約 1/4）
- やり直しは、戻したい時点の before を選んで `gh pr edit <URL> --body-file <scratchpad>/pr-shorten-<N>-before-<YYYYMMDD-HHMMSS>.md` する（最初の原本は最も古い before）

## やってはいけないこと

- 元本文を退避せずに `gh pr edit` する
- 字数を稼ぐために事実・数値・URL・判断理由を落とす（削るのは冗長表現と経緯。迷ったら折りたたみに移す）
- 元本文に無い事実を足す、曖昧化する、「未確認」を確認済みに書き換える
- 短縮案だけのファイルに追記分を書いて `gh pr edit` する（本文全体を置き換える前提なので、必ず完成した全文のファイルを渡す）
- 動作確認の該当項目（何を確認し結果がどうか）を折りたたむ
- テンプレートの見出し・順序を崩す
- 検品を飛ばして反映する（サブエージェントの報告をそのまま信じない。`grep` で突き合わせる）
