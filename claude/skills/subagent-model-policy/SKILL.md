# サブエージェントのモデル使い分け方針

サブエージェントを起動するときは、`model` パラメータを省略せず必ず明示する。
省略すると親セッションのモデル（Fable 5 等の上位モデル）を継承してしまい、コストが無駄に高くつく。

## 使い分け

| タスクの種類 | モデル指定 |
|---|---|
| 単純な調査（grep・git履歴・ファイル横断の事実確認など、手順が明確な調べ物） | `model: "sonnet"` |
| 複雑な調査・リサーチ（Web検索、設計判断・仕様解釈を含む調査、原因不明のデバッグ調査） | `model: "opus"` |
| 単純なコーディング・実装（機械的な編集、定型的な実装、テスト追加） | `model: "sonnet"` |

## 判断に迷うとき

- 「何を探すか」が明確なら Sonnet、「探しながら判断する」なら Opus
- 調査寄りの中間タスク（設計判断を含む調査など）→ Opus に倒す
- 複雑な設計判断を伴う実装 → Opus を検討してよいが、まずユーザーに確認する
- Workflow スクリプト内の `agent()` 呼び出しにも同じ方針を適用する（`opts.model`）
