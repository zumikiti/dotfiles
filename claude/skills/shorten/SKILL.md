# 文章の短縮（必要な情報だけに絞る）

文章を、読み手が 30 秒で要点を掴める形に絞る。考え方と守りを定義する核のスキルで、媒体ごとの手順・字数目標は媒体ごとのスキル（`pr-shorten` など）が持つ。

## 対象

- 対象: PR 本文・Issue 本文・Jira の description・ローカルの Markdown ファイルなど、常時表示と別置き（折りたたみ・付録など）の二層に分けられる文章
- 対象外: Slack 投稿
- 適用しない: `furikaeri-brushup`。あれは想起を優先して圧縮・集約を禁じるため、本スキルの考え方と逆になる
- PR 本文の短縮は `pr-shorten`、新規 PR の本文は `create-pr` を使う

## 考え方（限定合理性）

- 読み手の注意力・ワーキングメモリは有限で、全文は読まれない。最適解ではなく十分な解を素早く選べる文章が良い文章
- 30 秒で「なぜ・何を・何に気をつけるか」を掴める。先頭に結論・影響範囲・注意点を置く（結論を先、根拠を後ろ）
- 常時表示と別置きの二層に分ける。常時表示は判断に要る最小限、詳細は折りたたみ（`<details>`）や付録に置く
- 目的は全体字数の削減ではなく、**常時表示の認知負荷の削減**。全体が数 % しか減らなくても、常時表示が小さくなれば成功
- 字数・行数の数値目標は本スキルに書かない。数値は媒体ごとのスキルが持つ

## 既存の文章を書き換えるときの守り

優先順位は「事実の保持 > 常時表示の必須項目 > 字数目標」。

- 上書き前に原本を scratchpad（セッション固有の一時ディレクトリ。Claude Code では環境情報に示される Scratchpad directory）へタイムスタンプ付き（`<名前>-before-$(date +%Y%m%d-%H%M%S)`）で退避し、パスを報告する
- 事実・数値・URL・判断理由は消さず、別置きへ移す。削るのは冗長表現と経緯だけ。迷ったら別置きへ移す
- 元に無い事実を足さない。曖昧化もしない（例: 「ポートを変更」ではなく「ホスト 4566 → コンテナ 8333」）
- 「未確認」「推測」を確認済みに格上げしない。推測と確認済み事実の区別を元のまま保つ
- 検品: 元の URL・数値・バッククォート識別子を grep で突き合わせる（before / after は原本と短縮案のファイル）
  - URL: `comm -23 <(grep -oE 'https?://[^ )>]+' before | sort -u) <(grep -oE 'https?://[^ )>]+' after | sort -u)`（出力が空なら合格）
  - 数値: 同じ形で `grep -oE '[0-9][0-9.,]*'`（番号付きリストの `1.` 等で雑音が出るため、出力は目で判断する。箇条書き化による差は欠落ではない）
  - バッククォート識別子: 同じ形で `` grep -oE '`[^`]+`' ``
  - 「未確認」「推測」の語が before にあれば after にも残っているか
- `<details><summary>…</summary>` の後に空行を入れる（中の Markdown を効かせるため）。`<details>` は入れ子にしない
- ファイル末尾に改行を入れる

## 計測コマンド

**常時表示**は、すべての `<details>…</details>` の外側にあるテキスト（最初の `<details>` より前、ではない。節ごとに折りたたみが複数あり得る）。`wc -m` は必ず `LC_ALL=C.UTF-8` 付きで使う（`LC_ALL=C` だとバイト数になり日本語で約 3 倍になる）。

- 常時表示の字数: `perl -0pe 's/<details\b[^>]*>.*?<\/details>//gsi' <file> | LC_ALL=C.UTF-8 wc -m`
- 常時表示の行数（空行を除く）: `perl -0pe 's/<details\b[^>]*>.*?<\/details>//gsi' <file> | grep -c '\S'`（空行込みは `| wc -l`）
- 全体: `LC_ALL=C.UTF-8 wc -m <file>`

媒体固有の除外（PR の `## 動作確認` など）は媒体ごとのスキルが定義する。

## 直接呼ばれたときの振る舞い

1. 対象の文章を読み、原本を scratchpad へ退避してパスを報告する
2. 上記の考え方と守りに従って短縮案を作る
3. 短縮案と検品結果（grep の突き合わせの結果、計測値）を見せて止まる
4. ユーザーの承諾後に、対象へ反映する

deliberate: 専用の検品が無いので案の提示で止める。何度か使って問題が無ければ、反映まで自動にすることを検討する。
